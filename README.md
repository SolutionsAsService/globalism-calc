# Globalism Calc · Dependency Atlas

How dependent are countries, states and territories on others to survive? This app scores dependence per **category** (food, fuel & energy, trade exposure, medicine, minerals, manufactured goods, water) from public datasets kept in this repo, combines them into a **composite dependence / self-sufficiency index** with weights you can adjust, and shows the result on a world map, in a ranking table, in per-entity detail panels and in a compare view.

**Rule: no invented numbers.** Every value comes from a file in `data/raw/`. Missing data stays missing: it is shown as hatched on the map and "—" in tables, and it is left out of averages (never counted as 0). Categories with no dataset are labeled **data needed**.

## Stack

- **Vite + vanilla TypeScript** static site. No framework. Data is served as JSON from `/data`.
- **d3-geo / d3-zoom / d3-scale** for the choropleth. World map: [world-atlas](https://github.com/topojson/world-atlas) `countries-50m` (Natural Earth, public domain), vendored in `data/geo/` with no runtime CDN. The 50m resolution includes most small island territories.
- **Vitest** (+ jsdom) for importer, scoring, data-integrity and UI smoke tests.
- **Docker**: multi-stage build that serves `dist/` with a zero-dependency Node static server on `$PORT` (default 8080).

## Run

```bash
npm ci
npm run dev        # imports data, copies it to public/data, starts Vite on :5173
npm test           # 68 tests: importer (EIA, OWID CSV, derived ops), index math, real-data integrity (raw hashes, units, recomputation), UI smoke
npm run build      # re-imports data/raw -> data/datasets, type-checks, builds dist/
npm start          # serves dist/ on $PORT (default 8080); /healthz returns ok
```

Node ≥ 22.12 is required (Vite 8).

## Deploy (Shadw or anywhere)

- **Container**: `docker build -t globalism-calc . && docker run -p 8080:8080 globalism-calc`. The image listens on `$PORT` (default 8080) and exposes `/healthz`.
- **Static site**: `npm run build` and publish `dist/`. Paths are relative (`base: './'`) and routes are hash-based (`#/compare?keys=USA,CHN`), so it works from any path with no rewrite rules.

## Data model

```
data/
  raw/                 original files exactly as received (never edited by scripts)
    eia/               U.S. EIA International "SeriesExport" JSON files (energy), unchanged
    owid/              Our World in Data energy dataset CSV + codebook + sources file (Ember electricity, Energy Institute fuels), unchanged; PROVENANCE.md has URLs, retrieval time, SHA-256 and licences
  sources/*.source.json import specs: how to read one raw file + its metadata
  sources/*.derived.json derived datasets computed from normalized ones (e.g. imports − exports)
  datasets/*.json      normalized output (generated by npm run data:import, committed)
  categories.json      categories, default weights, and "wanted" datasets per category
  reference/
    entities.json      generated entity list (npm run data:entities)
    territories.json   which ISO codes are territories, plus sovereign/parent and display names
    subnational.json   states/provinces (empty for now; see key scheme)
    aliases.json       source label -> entity key, and labels to skip (aggregates, pseudo-areas)
  geo/countries-50m.json  vendored world-atlas TopoJSON (ISC license, Natural Earth public domain)
```

A normalized dataset (`data/datasets/<id>.json`):

```jsonc
{
  "schemaVersion": 1,
  "id": "wb-trade-pct-gdp-2022",
  "title": "Trade (% of GDP), 2022",
  "category": "trade",                       // must exist in data/categories.json
  "indicator": { "code": "NE.TRD.GNFS.ZS", "name": "Trade (% of GDP)", "unit": "% of GDP", "description": "..." },
  "source": { "name": "World Bank, WDI", "url": "https://...", "license": "CC BY 4.0", "citation": "..." },
  "year": 2022,
  "notes": ["..."], "caveats": ["..."],
  "scoring": { "include": true, "direction": "higher_more_dependent", "method": "percentile", "rationale": "..." },
  "import": { "from": "data/raw/...", "spec": "data/sources/...", "rowsRead": 265, "matched": 217,
              "missingValues": 59, "skipped": [{ "name": "World", "reason": "World Bank aggregate" }], "duplicates": [] },
  "rows": [ { "key": "ABW", "value": 169.7982829, "year": 2022, "sourceName": "Aruba" },
            { "key": "AND", "value": null, "year": 2022, "sourceName": "Andorra" } ]   // null = explicitly missing
}
```

### Entity keys

| Kind | Key | Examples |
|---|---|---|
| Country / territory with an ISO code | ISO 3166-1 alpha-3 | `USA`, `FRA`, `PRI` (Puerto Rico), `GRL`, `HKG` |
| No ISO code | World Bank code | `XKX` Kosovo, `CHI` Channel Islands |
| State / province / sub-national territory | `PARENT_ISO3-SUB`: parent ISO3 + the ISO 3166-2 suffix | ISO `US-CA` → `USA-CA`, ISO `IN-MH` → `IND-MH`, ISO `CA-NU` → `CAN-NU` |

Entity `type` is `country`, `territory` (with `parent`, the sovereign), `subnational` (with `parent`) or `other` (Antarctica and other uninhabited areas). To add states, put entries in `data/reference/subnational.json` (`{"key":"USA-CA","name":"California","type":"subnational","parent":"USA","aliases":["US-CA","California"]}`) and run `npm run data:entities`. Rows for them can then be imported like any other dataset, by name or by key. (They show in tables, detail and compare views; the world map only draws countries.)

## Adding a dataset (CSV/JSON → normalized)

1. **Drop the raw file** in `data/raw/` without editing it (e.g. a World Bank CSV export, a FAOSTAT CSV, or a JSON array).
2. **Write a source spec** `data/sources/<id>.source.json`:

   ```jsonc
   {
     "input": "data/raw/API_EG.IMP.CONS.ZS_DS2_en_csv_v2.csv",
     "format": "csv",
     "csv": { "skipLines": 4 },                 // World Bank CSVs have 4 preamble lines
     "entityField": "Country Code",             // ISO3/ISO2/key or a name (names go through aliases.json)
     "valueColumns": ["2018","2019","2020","2021","2022","2023"],  // wide files: newest non-empty year wins
     // or "valueField": "Value" with "yearField": "Year" (long files: latest year with a value per entity)
     // or "valueField": "value" with "year": 2022 (single-year files)
     // optional: "rowsPath": "data.items" (JSON), "where": {"Item": "Cereals"}, "scale": 1000 (source in thousands)
     "dataset": {
       "id": "wb-energy-net-imports",
       "title": "Energy imports, net (% of energy use)",
       "category": "energy",
       "indicator": { "code": "EG.IMP.CONS.ZS", "name": "Energy imports, net", "unit": "% of energy use" },
       "source": { "name": "World Bank WDI (IEA)", "url": "https://data.worldbank.org/indicator/EG.IMP.CONS.ZS", "license": "CC BY 4.0" },
       "year": 2023,
       "scoring": { "include": true, "direction": "higher_more_dependent", "method": "fixed-range", "range": [0, 100],
                    "rationale": "Already a share of consumption; net exporters (negative) score 0." }
     }
   }
   ```
3. **Run `npm run data:import`.** The importer is strict: any label it can't match fails the import and is listed. Add it to `data/reference/aliases.json` under `aliases` (label → key) or `nonEntities` (label → reason: regional aggregates, "World", pseudo-partners). Blank cells, `..`, `NA` and `null` become explicit missing values. Conflicting duplicate rows are an error.
4. **Run `npm test`** (it checks that committed datasets match a fresh import and that every dataset has complete metadata), then commit the raw file, the spec and the generated dataset. Any category with a scored dataset switches from "data needed" to scored automatically.

### Uploading a table straight into `data/datasets/`

Files uploaded through GitHub ("Add files via upload") into `data/datasets/` no longer break the site:

- `npm run data:import` (part of `npm run build`) detects any file there that is not a normalized dataset, moves it untouched to `data/raw/uploads/`, and
  - for **World Bank "most recent value" tables** (`indicator.code` + `entities[].most_recent_value_percent`) writes `data/sources/wb-<code>.source.json` itself: category from the indicator code (food, minerals, manufactured, energy, trade), percentile scoring, exports = context only, values older than 2010 dropped, aggregates skipped. Review the generated spec and commit it.
  - for any other shape it stops with a message: write a spec as above (see `itc-pharma-*.source.json` for an `entities` list with several value columns).
- `npm run data:prepare` skips (with a warning) anything in `data/datasets/` that is not normalized, so a stray upload can never take the app down.
- `python3 scripts/audit-uploads.py` checks uploaded tables for internal consistency (summary counts and min/max, value ↔ year ↔ status, USD = thousands × 1000, balance = exports − imports, duplicates) and lists stale observations.

The **Datasets & map** view (`#/data`) shows every loaded dataset → category → composite as a dependency map (line width = weight, dashed = context), and lets you switch datasets in or out of the score and change their weights and the category weights. Choices are stored in the browser (`localStorage`), the published data is unchanged.

### EIA International exports (`format: "eia-series"`)

Exports from the [EIA International data browser](https://www.eia.gov/international/data/world) ("SeriesExport-MM-DD-YYYY-HH-MM-SS.json": an array of series, one per country, with `iso`, `unit`, `productid`, `activityid` and annual `data`) are read directly. The importer flattens them to long rows (`iso, productid, activityid, unit, year, value, flag, marker`), so a spec looks like:

```jsonc
{
  "input": "data/raw/eia/petrol-import-SeriesExport-10-12-2026-18-11-05.json",
  "format": "eia-series",
  "entityField": "iso", "valueField": "value", "yearField": "year",   // latest year with a number per entity
  "where": { "productid": "57", "activityid": "3" },                  // one product/flow per dataset
  "unitField": "unit",       // every row's stated unit must equal dataset.indicator.unit, or the import fails
  "flagField": "flag",       // "p|1.5" -> value 1.5, flag "p" (kept on the row and shown in the UI)
  "markerField": "marker",   // "--", "NA", "ie" -> missing (never 0), counted in import.markers
  "keepSeries": true,        // also store the full annual series (trend chart, derived datasets)
  "dataset": { "indicator": { "unit": "TBPD", "unitLabel": "thousand barrels per day" }, "view": { "group": "crude-oil", "flow": "imports" }, ... }
}
```

`view` (group × flow) makes the category tab show a fuel picker and flow buttons instead of one long list, a per-entity balance table and a trend chart.

### Derived datasets (`data/sources/<id>.derived.json`)

`{"derive": {"op": "net", "imports": "<id>", "exports": "<id>"}, "dataset": {...}}` computes imports − exports; `{"op": "net-share", ..., "base": "<id>"}` computes 100 × (imports − exports) ÷ base; `{"op": "dependence", "supply": "<id>", "production": "<id>"}` computes 100 × (supply − production) ÷ supply (a fuel's net import dependence); `{"op": "electricity-exposure", ...}` computes the electricity import exposure (below). Inputs need `keepSeries`; for each entity the latest year where **all** inputs have a number is used (no mixing years), entities with no common year stay missing, and inputs with different units are refused. Derived specs may use other derived datasets; `npm run data:import` runs them in dependency order.

### Our World in Data CSV (`format: "csv"`, long)

The OWID energy CSV has one row per country and year. Specs use `"entityField": "iso_code", "entityFallbackField": "country"` (iso_code is blank for regions and for Kosovo, so the name is matched instead; regions and former states are listed in `aliases.json` → `nonEntities`), `"yearField": "year"`, `"minYear": 1990`, `keepSeries`, and record `source.sha256` of the raw file: the importer refuses a raw file whose hash changed, and the tests check every declared unit against the OWID codebook (`indicator.sourceUnit`). The CSV is parsed once per run (`readRowsCached`).

### Electricity import exposure (scored Fuel & energy indicator)

`data/sources/electricity-import-exposure.derived.json`, same country and year for every input:

```
exposure = 100 × [ max(N,0) + Σ_f g_f × clamp(d_f, 0, 1) ] ÷ ( G + max(N,0) )      f = coal, gas, oil
d_f      = (supply_f − production_f) ÷ supply_f
```

G generation, N net electricity imports, g_f generation from fuel f (Ember, TWh); supply/production of each fuel from the Energy Institute (TWh). A fuel with zero generation adds 0; a burned fuel with unknown dependence gives **no value** (only bounds, shown in the detail panel), and an exact value more than 2 years older than the latest generation data is dropped (`maxLagYears`). Limits: assumes power plants import the same share of a fuel as the whole economy; nuclear fuel (uranium) is not counted; net figures; electricity only. Full text on the Method page.

**Scoring choice:** `scoring.include: true` (fixed range 0–100) — it fixes the "Japan at 0 %" problem of direct electricity trade (Japan ≈ 68 %, South Korea ≈ 60 %, Taiwan ≈ 85 %, Singapore ≈ 95 %, Germany ≈ 33 %, France ≈ 5 %, US ≈ 0.4 %). Turn it off with `scoring.include: false` in that file (then `npm run data:import`), or set the Fuel & energy weight to 0 in the app. The EIA electricity net-import share stays context only (it is the direct part of the exposure; scoring both would double count).

### Scoring methods (0–100, 100 = most dependent)

| method | formula | use for |
|---|---|---|
| `fixed-range` | `100 × clamp((v − lo) / (hi − lo), 0, 1)` | values that already are shares (import % of supply): reads literally |
| `minmax` | `100 × (v − min) / (max − min)` over entities with data | bounded indicators without a natural range |
| `log-minmax` | min–max on `log10(1 + v)` | heavy-tailed absolute values |
| `percentile` | `100 × (#below + ½(#equal − 1)) / (n − 1)` | unbounded ratios (e.g. trade % GDP) |

`direction: "lower_more_dependent"` inverts the score (`100 − s`). **Category score** = weighted mean (indicator `weight`, default 1) of included indicator scores that exist for the entity. **Composite** = `Σ(w_c × s_c) / Σ(w_c)` over categories with a score and `w_c > 0`. Missing categories are excluded and listed. Self-sufficiency = 100 − composite. Weights are adjustable in the UI and stored in localStorage.

Share-of-imports indicators describe the *composition* of imports, not import dependence, which is why they are rank-scored and flagged in their caveats.

## Most useful next datasets

1. **Energy**: World Bank `EG.IMP.CONS.ZS` *Energy imports, net (% of energy use)* CSV (fixed-range 0–100) for whole-economy energy (transport and heat, not just power); uranium supply by country, to count imported nuclear fuel in the electricity exposure; fuel import dependence for small countries that EI does not list separately (most of the 114 entities that now only have bounds burn oil for power).
2. **Food**: FAOSTAT *Suite of Food Security Indicators*, "Cereal import dependency ratio" (fixed-range), and/or Food Balance Sheets (import quantity ÷ domestic supply).
3. **Water**: FAO AQUASTAT *Dependency ratio* (% of renewable water from outside the borders).
4. **Manufactured / minerals**: WDI `TM.VAL.MANF.ZS.UN`, `TM.VAL.MMTL.ZS.UN`; USGS net import reliance.
5. **Medicine**: UN Comtrade HS 30 imports with production data.
6. **Trade**: `NE.IMP.GNFS.ZS` *Imports (% of GDP)*, closer to dependence than total trade.
